# Error Codes

When making requests to the ForVoyez API, you may encounter various error codes and error messages that indicate the status of your request. This page provides a comprehensive list of the error codes and messages you may receive, along with their descriptions and possible solutions.

## HTTP Status Codes

The ForVoyez API uses standard HTTP status codes to indicate the success or failure of a request. Here are the common status codes you may encounter:

- `200 OK`: The request was successful.
- `400 Bad Request`: The request was invalid or cannot be served.
- `401 Unauthorized`: The request lacks valid authentication credentials, or the account has no credit left.
- `500 Internal Server Error`: The server encountered an unexpected condition that prevented it from fulfilling the request.

## ForVoyez API Error Messages

In addition to the standard HTTP status codes, the ForVoyez API returns specific error messages in the response body to provide more detailed information about the error. These error messages are accompanied by the corresponding HTTP status code.

Here are the ForVoyez API error messages you may encounter:

- `Unauthorized, missing Authorization header`
  - Status Code: `401`
  - Description: The `Authorization` header is missing in the request, or it does not start with `Bearer `.
  - Solution: Send your API key in the `Authorization: Bearer YOUR_API_KEY` header.

- `Unauthorized, invalid token`
  - Status Code: `401`
  - Description: The request lacks valid authentication credentials.
  - Possible Causes:
    - The provided API key is invalid or malformed.
    - The API key has passed the expiration date set when it was created.
    - The API key has been deleted from the dashboard (deleting a key revokes it immediately).
  - Solution: Create a new API key in the [dashboard](https://forvoyez.com/app/tokens) and update your application.

- `Unauthorized, no credit left`
  - Status Code: `401`
  - Description: The user has insufficient credits to make the request.
  - Solution: Wait for your next subscription renewal, upgrade your plan, or buy a credit pack. See [Limits and Quotas](/limits-and-quotas).

- `Bad Request, No file uploaded`
  - Status Code: `400`
  - Description: The `image` parameter is missing in the request.
  - Solution: Ensure that you are including the `image` parameter in the multipart/form-data request body.

- `Bad Request, Invalid image file`
  - Status Code: `400`
  - Description: The uploaded file is not a valid image format.
  - Solution: Verify that the uploaded file is in one of the supported image formats: JPEG, JPG, PNG, WebP, or GIF.

- `Invalid schema: ...`
  - Status Code: `400`
  - Description: The `schema` field is over the schema limits. The rest of the message names the limit:
    - `Invalid schema: at most 20 fields are allowed`
    - `Invalid schema: field names must be at most 64 characters`
    - `Invalid schema: field descriptions must be at most 1000 characters`
    - `Invalid schema: "__proto__" is not allowed as a field name`
  - Solution: Reduce your schema to at most 20 fields, with field names up to 64 characters and descriptions up to 1,000 characters. See [Data Schemas](/data-schemas#schema-validation). No credit is used.

- `Internal Server Error`
  - Status Code: `500`
  - Description: An unexpected error occurred on the server side.
  - Solution: If you encounter this error repeatedly, please contact our support team for assistance.

- `Image processing failed: ...`
  - Status Code: `500`
  - Description: The image could not be processed, for example because it is larger than 10 MB. The rest of the message gives the cause. Uploads much larger than 10 MB can instead return `500` with the message `Internal Server Error`.
  - Solution: Send a smaller image (up to 10 MB) in a supported format.

## Error Response Format

When an error occurs, the ForVoyez API returns an error response with the appropriate HTTP status code and a JSON body (`Content-Type: application/json`). The `error` field contains a human-readable message.

Example error response (`401 Unauthorized`):

```json
{
	"error": "Unauthorized, missing Authorization header"
}
```

## Handling Errors

When consuming the ForVoyez API, it's important to handle errors gracefully in your application. Here are some best practices for error handling:

- Check the HTTP status code of the response to determine the general category of the error.
- Read the `error` field of the JSON response body to understand the specific cause of the error.
- Display user-friendly error messages to your users based on the error message received.
- Implement appropriate error logging and monitoring mechanisms to track and investigate errors.
- If you encounter persistent or unexpected errors, reach out to our support team for further assistance.

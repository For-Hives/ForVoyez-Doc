## Details of Parameters and Responses

Each endpoint in the ForVoyez API requires specific parameters to be included in the request. These parameters are provided as form fields in a multipart/form-data request.

The API responses are returned in JSON format and contain the requested data or relevant error information. The response format varies based on the endpoint and the success or failure of the request.

Here's an example of a request and response for the `/describe` endpoint:

<CodeGroup>
```bash {{title: 'cURL Request'}}
curl -X POST \
-H "Authorization: Bearer YOUR_API_KEY" \
-F "image=@/path/to/your/image.jpg" \
-F "schema={\"title\":\"A short title for the image\",\"alternativeText\":\"Alt text for screen readers\",\"caption\":\"A one-sentence caption\"}" \
-F "keywords=playful,kittens" \
-F "context=Playful kittens" \
-F "language=en" \
https://forvoyez.com/api/describe
```

```json {{ title: 'JSON Response' }}
{
	"title": "Playful Kittens",
	"alternativeText": "Two kittens playing with a ball of yarn",
	"caption": "Adorable kittens having fun and being mischievous"
}
```

</CodeGroup>

The available parameters for the `/describe` endpoint are:

- `image`: The image file (required)
- `schema`: JSON string with a flat object mapping each output field to a description (optional, see [Data Schemas](/data-schemas))
- `keywords`: Comma-separated list of keywords (optional)
- `context`: Additional context about the image (optional)
- `language`: Desired language for the output (optional, defaults to 'en')

For more details on the parameters and responses for each endpoint, refer to the individual endpoint documentation.

## Error Codes and Error Messages

If a request to the ForVoyez API fails, you'll receive an appropriate HTTP status code along with a JSON error body. Its `error` field provides more information about the cause of the error and helps you troubleshoot the issue.

Here are the common error codes you might encounter:

- `400 Bad Request`: The request is invalid or missing required parameters.
- `400 Bad Request, the body must be multipart/form-data`: The request body is not a `multipart/form-data` form (let your HTTP client set the `Content-Type` header).
- `400 Bad Request, No file uploaded`: The `image` parameter is missing in the request.
- `400 Bad Request, Invalid image file`: The uploaded file is not a JPEG, PNG, WebP, or GIF image (the format is detected from the file content).
- `400 Invalid schema: ...`: The `schema` has more than 20 fields, a field name longer than 64 characters, a description longer than 1,000 characters, or a field named `__proto__` (see [Data Schemas](/data-schemas#schema-validation)), or it asks for a longer answer than the API can return (about 1,500 words for all fields together).

- `401 Unauthorized`: Authentication failed.
- `401 Unauthorized, missing Authorization header`: The `Authorization` header is missing in the request.
- `401 Unauthorized, invalid token`: The provided API key is invalid, has expired, or has been deleted from the dashboard.
- `401 Unauthorized, no credit left`: The user has insufficient credits to make the request.

- `413 Image too large: the maximum is 10 MB`: The image is over 10 MB, or the request body is over 11 MB.

- `500 Internal Server Error`: The metadata could not be generated (for example, the AI model failed) or another unexpected error occurred on the server side. No credit is used, so you can retry the request.
- `500 Image processing failed: ...`: The image is a supported format but could not be decoded (truncated or corrupt file).

The error response is sent with `Content-Type: application/json` and an `error` field with more details. For example, a request without an image returns `400 Bad Request` with this body:

```json
{
	"error": "Bad Request, No file uploaded"
}
```

For a complete list of error codes and their meanings, refer to the [Error Codes](/error-codes) documentation.
